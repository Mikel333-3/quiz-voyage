# Quiz time

QUIZ TIME 🇭🇹 — PROMPT MAÎTRE POUR LOVABLE



1. MISSION



Crée une première version fonctionnelle de Quiz Time, une plateforme de quiz éducatifs destinée en priorité aux élèves haïtiens.



IMPORTANT : Quiz Time ne doit surtout pas ressembler à un site scolaire classique, un LMS ou un dashboard SaaS.



L'objectif est de créer un véritable jeu éducatif.



Principe produit :



«« Apprendre devient un jeu. »»



L'utilisateur doit avoir l'impression d'entrer dans un univers numérique futuriste où il peut jouer, progresser, gagner de l'XP, améliorer son niveau, débloquer des récompenses et se mesurer aux autres joueurs.



Les documents fournis avec ce prompt constituent la référence principale pour la vision, l'architecture, les fonctionnalités et le design du produit.



---



2. DOCUMENTS ET IMAGES FOURNIS



Je vais te fournir :



- le blueprint complet de Quiz Time ;

- le document de vision et roadmap ;

- plusieurs images de référence représentant la direction visuelle souhaitée.



Utilisation des images



NE COPIE PAS les images pixel par pixel.



Les images sont des références visuelles et direction artistique.



Inspire-toi notamment :



- de l'ambiance futuriste ;

- de la profondeur visuelle ;

- de la palette sombre ;

- des interfaces lumineuses ;

- de la hiérarchie des informations ;

- des cartes ;

- du glow ;

- du contraste ;

- de la sensation de jeu vidéo ;

- de la présentation mobile et desktop.



Tu peux améliorer, adapter et réinterpréter le design.



Le résultat final doit être une identité Quiz Time cohérente, et non une copie des images.



---



3. DIRECTION ARTISTIQUE



Utilise principalement :



- bleu nuit / presque noir comme base ;

- bleu électrique ;

- cyan lumineux ;

- blanc ;

- touches de couleurs différentes pour distinguer certaines catégories ou états.



Utilise avec modération :



- glassmorphism ;

- transparences ;

- bordures lumineuses ;

- gradients ;

- glow ;

- ombres profondes ;

- particules ;

- éléments futuristes.



L'interface doit être premium, moderne, dynamique et immersive.



Évite cependant de surcharger l'écran.



Les effets visuels doivent servir l'expérience et non la ralentir.



---



4. RESPONSIVE DESIGN



Construis le projet mobile-first.



Le téléphone est une plateforme principale.



L'interface doit fonctionner parfaitement sur :



- petits smartphones ;

- grands smartphones ;

- tablettes ;

- ordinateurs portables ;

- écrans desktop.



Sur mobile :



- navigation simple ;

- boutons suffisamment grands ;

- texte lisible ;

- quiz sans scrolling inutile ;

- interface utilisable à une main lorsque possible.



Sur desktop :



- exploiter davantage l'espace ;

- conserver une hiérarchie claire ;

- proposer une expérience de jeu plus immersive.



Ne fais pas simplement une version desktop réduite sur mobile.



---



5. STRUCTURE PRINCIPALE



Crée les sections/pages principales suivantes :



🌌 Lobby



Page centrale de Quiz Time.



Elle doit afficher :



- logo Quiz Time ;

- message de bienvenue ;

- niveau du joueur ;

- XP ;

- progression ;

- série actuelle ;

- classement ;

- nombre de joueurs en ligne ;

- bouton principal JOUER ;

- accès aux modes de jeu ;

- accès rapide à Haïti Quest ;

- notifications ou récompenses disponibles.



Le Lobby doit ressembler à un centre de jeu futuriste, pas à une homepage classique.



---



6. 🎮 JOUER



Créer une page permettant de choisir le mode de jeu.



Modes principaux :



🧠 Entraînement



Apprendre et s'entraîner sans forte pression.



⚡ Chrono



Répondre correctement et rapidement.



📝 Examen



Mode destiné à préparer progressivement aux examens.



🎲 Défi aléatoire



Le système sélectionne automatiquement une combinaison de matière, niveau, difficulté et questions.



🇭🇹 Haïti Quest



Mode consacré à Haïti.



Présente ces modes comme des modes de jeu, pas comme des catégories scolaires.



---



7. 🧭 SÉLECTION DE PARTIE



Après avoir choisi un mode, permettre au joueur de préparer sa partie.



Exemples :



- matière ;

- niveau ;

- difficulté ;

- nombre de questions ;

- règles du mode ;

- XP/points potentiels.



Utilise une présentation inspirée d'une préparation de mission.



Exemples de textes :



SELECT YOUR MISSION



READY?



LANCER LA PARTIE



---



8. ⚡ ÉCRAN QUIZ



C'est le cœur de l'application.



Créer une interface extrêmement claire et réactive.



Afficher :



- question actuelle ;

- progression ;

- chronomètre lorsque nécessaire ;

- score ;

- combo ;

- question ;

- quatre réponses possibles ;

- feedback après réponse.



Exemple :



QUESTION 07 / 10



Puis une question.



Les réponses doivent être présentées sous forme de grandes cartes interactives.



Bonne réponse



Afficher une réaction visuelle rapide :



- glow ;

- animation ;

- points gagnés ;

- progression du combo.



Mauvaise réponse



Afficher un feedback clair mais pas agressif.



La transition vers la question suivante doit être rapide.



---



9. 🔥 SYSTÈME DE COMBO



Créer un système de séries de bonnes réponses.



Exemples :



COMBO x2



COMBO x3



COMBO x5



etc.



Les combos donnent des bonus de score.



L'animation peut devenir progressivement plus forte lors des paliers importants.



---



10. 🏆 RÉSULTATS



Après une partie, afficher un écran ressemblant à la fin d'une partie de jeu.



Ne pas présenter cela comme une simple note scolaire.



Afficher :



- résultat final ;

- score ;

- bonnes réponses ;

- erreurs ;

- pourcentage ;

- meilleur combo ;

- XP gagnée ;

- progression du niveau ;

- badges éventuellement débloqués ;

- nouveau rang si applicable.



Boutons :



REJOUER



RETOUR AU LOBBY



VOIR LE CLASSEMENT



Ajouter une animation de célébration légère.



---



11. 🏆 CLASSEMENT



Créer un leaderboard de jeu.



Afficher :



- Top 3 ;

- position du joueur actuel ;

- pseudo ;

- avatar ;

- XP ;

- niveau.



Prévoir des onglets :



- Global ;

- Amis ;

- Écoles.



Pour la V1, les fonctionnalités qui nécessitent un véritable backend peuvent être simulées avec des données locales réalistes.



Le joueur actuel doit être clairement identifiable.



---



12. 👤 PROFIL



Créer un profil qui ressemble à une fiche de personnage de jeu vidéo.



Afficher :



- avatar ;

- pseudo ;

- niveau ;

- XP ;

- progression ;

- nombre de parties ;

- taux de réussite ;

- meilleur combo ;

- badges ;

- statistiques ;

- école si disponible.



Le profil ne doit pas ressembler à une page administrative.



---



13. 🏅 RÉCOMPENSES



Créer une collection de badges.



Exemples :



- FIRST WIN

- SPEEDSTER

- PERFECT RUN

- STREAK MASTER



Afficher :



- badges débloqués ;

- badges verrouillés ;

- conditions de déblocage.



Lorsqu'un badge est débloqué, créer une animation visuelle agréable.



---



14. 🇭🇹 HAÏTI QUEST



C'est une fonctionnalité importante et une signature de Quiz Time.



Créer un mode entièrement consacré à Haïti.



Concept :



«« Explore ton pays. Teste tes connaissances. »»



Créer une carte stylisée d'Haïti.



La carte doit permettre à terme de représenter :



- départements ;

- régions ;

- zones débloquées ;

- lieux importants ;

- catégories.



Catégories initiales :



- Histoire ;

- Géographie ;

- Culture ;

- Patrimoine ;

- Sciences et environnement ;

- Institutions et citoyenneté ;

- Personnalités et littérature ;

- Questions surprises.



La progression doit donner l'impression d'explorer Haïti.



Pour la V1, il est acceptable de créer une version simplifiée mais visuellement convaincante.



---



15. NAVIGATION



Sur desktop, créer une navigation claire permettant d'accéder aux grandes sections.



Sur mobile, utiliser une navigation adaptée au téléphone.



Navigation principale :



- Accueil / Lobby

- Jouer

- Haïti Quest

- Classement

- Récompenses

- Profil



Ajouter également :



- Paramètres ;

- Aide.



---



16. ÉCRAN D'INTRODUCTION



Créer un écran d'introduction immersif.



Il doit comporter :



- fond sombre ;

- logo Quiz Time ;

- cerveau lumineux ou élément graphique représentant l'intelligence ;

- particules discrètes ;

- glow cyan ;

- petite animation ;

- progression courte.



Messages possibles :



INITIALIZING...



LOADING KNOWLEDGE...



CONNECTING PLAYERS...



Puis transition vers le Lobby.



IMPORTANT : cette animation doit rester courte et ne jamais bloquer inutilement l'utilisateur.



---



17. MICRO-INTERACTIONS



Ajouter des micro-interactions modernes :



- boutons réactifs ;

- hover desktop ;

- tap mobile ;

- transitions entre pages ;

- progression XP animée ;

- score qui s'incrémente ;

- combo animé ;

- feedback immédiat lors d'une réponse ;

- badge qui se débloque ;

- transitions douces.



Les animations doivent rester raisonnables afin de fonctionner correctement sur des appareils modestes.



---



18. DONNÉES DE DÉMONSTRATION



Pour la première version, si aucun backend n'est encore connecté, utiliser des données mockées réalistes.



Créer par exemple :



- plusieurs joueurs ;

- plusieurs matières ;

- plusieurs questions ;

- XP ;

- niveaux ;

- badges ;

- scores ;

- classements ;

- statistiques.



Mais structure le code de manière à ce que ces données puissent facilement être remplacées plus tard par une vraie base de données.



---



19. ARCHITECTURE TECHNIQUE



Crée une architecture propre et maintenable.



Sépare clairement :



- composants UI ;

- pages ;

- données ;

- logique du quiz ;

- système de score ;

- système XP ;

- système de combo ;

- navigation.



Évite de mettre toute l'application dans un seul fichier.



Le code doit être suffisamment propre pour qu'une autre personne puisse ensuite le reprendre et l'améliorer.



---



20. V1 : NE PAS SURCONSTRUIRE



IMPORTANT.



Ne cherche PAS à créer immédiatement :



- vrai multijoueur temps réel ;

- Voice Battle ;

- IA complexe ;

- système vocal avancé ;

- tournois complexes ;

- système complet de compétition entre écoles ;

- infrastructure offline complexe.



Ces fonctionnalités appartiennent aux versions futures.



La priorité est :



UNE V1 JOUABLE, BELLE, RAPIDE ET AMUSANTE.



---



21. OBJECTIF FINAL DU PROTOTYPE



À la fin de cette première génération, je dois pouvoir :



1. ouvrir Quiz Time ;

2. voir l'introduction ;

3. arriver dans le Lobby ;

4. consulter mon profil ;

5. choisir un mode ;

6. choisir une matière/niveau ;

7. lancer un quiz ;

8. répondre aux questions ;

9. voir mon score ;

10. gagner de l'XP ;

11. voir mon combo ;

12. obtenir un résultat ;

13. consulter le classement ;

14. consulter les récompenses ;

15. explorer Haïti Quest.



Le parcours doit être cohérent du début à la fin.



---



22. IMPORTANT : QUALITÉ VISUELLE



Ne produis pas un simple template générique de dashboard.



Je veux une identité visuelle forte.



Le résultat doit immédiatement donner l'impression :



«« Ceci est un jeu éducatif futuriste. »»



et non :



«« Ceci est un site web avec quelques quiz. »»



Le blueprint fourni précise justement que Quiz Time ne doit pas être un site scolaire traditionnel, un LMS, un dashboard SaaS ou une copie visuelle de Kahoot/Quizizz.



---

Tu peux reprendre :

24. AVANT DE TERMINER



Vérifie toi-même :



- toutes les pages fonctionnent ;

- tous les boutons principaux ont une action ;

- la navigation fonctionne ;

- le quiz fonctionne ;

- les réponses fonctionnent ;

- le score fonctionne ;

- l'XP fonctionne ;

- le combo fonctionne ;

- les résultats fonctionnent ;

- le classement fonctionne ;

- le profil fonctionne ;

- Haïti Quest est accessible ;

- le responsive fonctionne ;

- aucun écran important n'est vide ;

- aucune image ou ressource essentielle n'est cassée.



Si une fonctionnalité avancée ne peut pas être réellement implémentée sans backend, crée une version prototype/mock fonctionnelle, sans prétendre qu'elle est réellement connectée à des joueurs réels.



---



25. RÈGLE FINALE



Ne cherche pas à construire toute la vision de Quiz Time immédiatement.



Construis d'abord un excellent prototype V1.



Le produit doit être :



Simple à comprendre.



Rapide à utiliser.



Amusant.



Visuellement impressionnant.



Pensé pour les élèves haïtiens.



Facile à faire évoluer.



Commence par construire l'expérience complète V1 et assure-toi que le parcours utilisateur fonctionne avant d'ajouter des fonctionnalités avancées.
